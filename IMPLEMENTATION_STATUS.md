# IMPLEMENTATION_STATUS

Updated: 2026-11-07. Spec baseline: R3 (MG-ARTWORK-2026-1107-R3), ₹12.5 lakh base. **Not production-ready.** This is the first vertical slice of a much larger build.

## Baseline
- No repository was supplied, so this one was created empty at `artwork-saas/` (local, git, single branch). No prior code, dependencies or tests existed.
- Stack: Next.js 15 (App Router) + TypeScript 5.9, PostgreSQL 16, `sharp` for image inspection, `zod`, `vitest`. Modular monolith under `src/server/`.
- Decisions: scrypt password hashing; opaque session tokens stored hashed; tenant context resolved from an unrevoked membership, never trusted from the client; ledgers are integer paise, append-only (DB trigger), idempotent by key.
- The separate physical-printing Framer project was never accessed. The 75-surface Framer design for this product lives in a different (Framer) project and was not used as a source here.

## Implemented and tested (183 automated tests, real PostgreSQL)
- Sign-in/out, session expiry, revoked membership, duplicate/weak credentials. Origin check on mutating API calls.
- Deny-by-default policy; tenant + owner isolation for projects, files, quotes; not-found instead of forbidden to prevent ID probing.
- Upload inspection: JPG/PNG only, 25 MB, 40 MP, truncated/corrupt rejected, embedded vs untagged profile reported.
- Settings validation: 500 mm per side, 80 MP including bleed.
- Projects with revision-checked, server-confirmed saves; concurrent same-revision saves: one wins.
- Quote (15 min expiry, stale-on-change), atomic reservation of customer credit and vendor processing credit, idempotent reserve, cancel-before-dispatch release, running job keeps hold; 20-way concurrency tests for both ledgers.
- Identity: registration with email verification (login blocked until verified), password reset (1 h, single-use, newer request voids older, ends sessions), staff invites (7 days, single-use, cannot take over an existing account), last-admin protection under concurrency, audit rows for these actions. Emails go to `email_outbox`; **no sender is wired**, so nothing is actually delivered yet.
- Processing: worker with SKIP LOCKED leases, heartbeats, attempt records, expiry reaper (bounded requeue, then fail + release), server export engine (mirror-edge bleed, RGB PNG with dpi metadata, independent output validation incl. dimensions), output + entitlement + credit consumption committed in one transaction gated on lease ownership (zombie workers cannot double-charge), failure releases holds, cancellation-during-run resolved against outcome, owner-only 90-day checksum-verified download with free re-download. Run with `npm run worker` is not wired; use `npx tsx scripts/worker.ts`.
- Editor and formats: shared geometry module (preview and export place the image identically), position/rotation/scale/fit/fill honoured by the real export, effective-dpi warning, exports to PNG, JPG, TIFF (LZW) and single-page PDF with trim and bleed boxes (no PDF/X claim), each independently validated. RGB/sRGB only; CMYK deliberately not offered until a licensed or client-supplied profile exists.
- Browser check (Playwright against real server + worker; `tests/e2e/editor-flow.cjs`, manual run, needs dev DB seeded): login, upload, canvas paints, rotate swaps halves, undo restores, dpi warning, arrow-key nudge autosaves, price, hold, worker output, PDF download; no horizontal overflow at 390 px.
- Vendor side: vendor registration (pending until activated), branding, public portal lookup (branding only, active vendors only), immutable plan versions, subscription state machine (pending/active/grace/expired; 7-day grace; reminders at 7 and 1 day deduplicated per period; renewal extends from period end or restarts after expiry; scheduled plan change at next renewal, no proration), staff seats enforced at invite and acceptance, role changes with last-admin protection, configured prices (vendor retail + platform processing; **no hidden defaults**; direct channel has no vendor charge), counter workflow (customer record, external payment record with receipt number, admin override with reason, vendor-credit-only reservation, no ledger entry for cash), vendor overview. Expired vendors cannot start paid work but can still download.
- `activateSubscription` has no HTTP route on purpose: only a verified provider payment event may call it. Nothing in the app can mark a subscription paid today.
- Public website: 12 pages (home, software, services, how it works, plans, pricing, FAQ, contact, terms, privacy, refund, acceptable use) under `src/app/(public)`, one h1 and a unique title each, sitemap.xml and robots.txt, skip link, mobile-checked (no horizontal overflow at 390 px). Content comes from real records (plans, direct-store price) or an honest empty state. **Legal pages never contain application-written text**: they show "not published yet" until the platform owner publishes approver-supplied versions (immutable, versioned). Enquiry form: field errors, consent record, honeypot, per-source/per-email limits (concurrency-safe), reference number, staff queue API with close-needs-note. Store landing pages (`/store/[slug]`) and customer registration resolve the store from the slug server-side. Vendor signup records the chosen plan, applied at first activation.
- Business workspaces: organisation with one administrator + up to nine members (invites count against seats, race-safe), invite acceptance only by the signed-in customer whose own email matches (no account creation or takeover), atomic admin transfer (never zero or two admins), removal blocked for the administrator. Shared credit is its own ledger account; organisation work never touches personal credit; vendor processing credit is still charged. Per-member monthly caps (IST calendar month) checked atomically with the shared balance and vendor credit: member row locked first, then accounts in id order. Releases restore capacity; lowering a limit below usage only blocks new spend; removed members cannot reserve. Private/shared projects: the administrator gets no extra access to private artwork, files or outputs (charge metadata only); shared = read-only for active members; removed members lose organisation projects and files. Usage report and CSV (admin-only, audited, formula-safe).
- Retention and library (Part 7): `/library` lists the customer's finished files with 90-day countdown, 7-day warning state, expired/removed wording, free re-download while retained, delete request (confirm step; links stop immediately), and an own-records credit/charges statement. `runRetention` (hourly via `scripts/scheduler.ts`) queues one 7-day warning email per file (deduplicated, safe to rerun), deletes live copies after expiry or deletion request, treats an already-missing file as done (crash recovery), refuses storage keys that escape the storage directory, records failures (`purge_error`, `purge_attempts`) and retries next run. Staff placed holds block purge; ledger and file metadata are never deleted. `job_runs` records last run/result per task; `GET /api/platform/runs` shows it to staff only. Not done: purge of original uploads/previews and temporary processing files, version cap/archive, ticket-driven deletion.
- Platform admin (Part 8): `/admin` for platform staff (login sends staff there): enquiry queue (take, close with resolution note, reopen), stores and subscriptions table (read-only; nothing can mark a store paid), processing price, plan versions, policy status and publish form (approver name required, versions immutable, bodies not shown in the overview), direct store create/link, scheduled-work last run and purge failures. Support staff can view and work enquiries but have no edit forms for price, plans, policies or direct store; the server enforces this independently of the UI. `GET /api/platform/overview` is staff-only and returns no artwork, files, balances or policy text. Browser-checked as owner, support and customer (`tests/e2e/admin-flow.cjs`). Not done: tenant suspend/close, plan retirement, enquiry assignment to named staff, policy version history view.
- Sign-in security (Part 9): failed sign-ins are counted per email and per source (5 / 30 in 15 minutes; same answer for unknown emails; a locked email gets no password check). Optional authenticator-app two-step sign-in (RFC 6238, tested against the RFC vector): the password step returns only a short-lived challenge (5 min, 5 tries); wrong codes count toward the lockout, and a correct password does not clear the count when two-step is on, so a stolen password cannot farm code guesses; a used code cannot be replayed; secrets are AES-256-GCM encrypted (production/staging refuse to enrol without `MFA_ENC_KEY`); 10 single-use hashed recovery codes shown once, use queues a notice and is audited. Roles in `MFA_REQUIRED_ROLES` (default platform_owner, platform_support) get an enrolment-only session until set up and cannot turn it off. Assisted reset (platform owner, or vendor admin within their tenant; never self; reason required) clears MFA, signs the user out, notifies and audits. `/account/security` page with QR and manual key.
- Email delivery (Part 10): `scripts/mailer.ts` (`npm run mailer`) delivers the `email_outbox`. 13 transactional templates (plain text; no legal text authored), links built from `APP_URL`, dates in IST. At-least-once delivery with leased rows (SKIP LOCKED; two senders never send the same row), stable Message-ID, backoff 1/5/30/120 min, give up after 5 attempts or on a 5xx, reason kept in `last_error`; tokens are scrubbed from the row once finished; bad recipient (CR/LF) or unknown template fails without sending. Fails closed: with no driver, or in production/staging with the file driver or incomplete SMTP settings, nothing is sent or marked sent, and `/admin` shows "NOT BEING SENT" with the waiting count. Drivers: `smtp` (nodemailer; TLS required on port 587 in production) and `file` (development only). Verified against a real SMTP conversation in tests and the file driver on the dev DB. Also added the missing `/invite` page for staff invitations.
- Support and closure (Part 11): `/support`, `/support/[id]`: tickets with category, optional link to a project/job/output/quote the requester can read (anything else is "not found"), public replies, staff-only notes, assignment (store admin; platform owner once escalated), escalation (reason plus a named accountable platform person; the link travels, file access does not), resolution that needs evidence, reopen (14 days, max 3), requester close, auto-close after 7 days (scheduler task `account_maintenance`), email notices carry only the reference. A payment ticket cannot be resolved while its job or held money is unsettled. `/account/data`: own-data export (JSON, 7-day expiry, staff notes excluded) and customer account closure: blocked by running jobs, held funds, leftover credit or organisation admin role, then password (and authenticator code) re-check, access stops at once, live files deleted 7 days later unless an investigation hold applies; payment records, tickets and audit log stay; the email stays reserved so re-registering does not reopen the old workspace. Not done: attachments, vendor closure (SC-034), owner-approved reopening of a closed account, refund/settlement of leftover credit (payments blocked), business-admin export.
- Storage and queue (Part 12): all file reads/writes/deletes go through `src/server/storage.ts`. Drivers: `local` (development; refused in staging/production) and `s3` (AWS SDK; works with any S3-compatible bucket; private objects, optional server-side encryption, https required in production, default credentials chain if no keys). Keys are server-generated and checked against traversal; a missing object is reported (`file_missing`), never silently ignored; deleting an absent object counts as deleted. `npm run check:storage` writes, reads back, compares and deletes a probe object: run it against the real bucket before go-live. `npm run dev:s3` starts a local S3-compatible server. Tested on both drivers with the same contract, and the full pipeline (upload, job, download, deletion request, purge) on S3 against an S3-protocol server. Redis (`REDIS_URL`, optional) carries wake-up signals only: reserving a quote signals after the database commit, the reaper signals requeued jobs, workers wait on Redis with a 5 s fallback poll. Jobs, leases and money stay in Postgres, so Redis loss, restart or duplicate signals cannot lose or double-run a job or charge twice (tested against a real redis-server, including killing and restarting it). `/admin` shows waiting/running jobs, oldest waiting age, storage mode and Redis state. Browser editor flow run on S3 + Redis + worker.
- UI: /vendor (overview, prices, branding, staff), /counter (4-step flow), login, forgot/reset/verify pages, project list, editor (numeric settings, upload, autosave status, conflict banner, quote, reserve).
